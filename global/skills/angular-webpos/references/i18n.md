# Traducciones (ngx-translate)

Todo texto visible al usuario va traducido en **español e inglés**. Las traducciones son objetos TypeScript,
no JSON, y se cargan una sola vez en `app.component.ts` (`translationService.loadTranslations(enLang, esLang)`).
No cargues traducciones en cada componente.

## Archivos

```
src/app/_config/lang/
├── es.ts / en.ts                         ← raíz: importa cada feature y la cuelga de una clave
├── common/common.{es,en}.ts              ← COMMONS: botones, mensajes, confirmaciones, tabla…
└── <feature>/<entidad>/<entidad>.{es,en}.ts
```

Archivo de feature (plantilla: `assets/plantilla-crud/i18n/item.es.ts`):

```typescript
export const item = {
  TITLE: 'Items',
  BTN: { ADD: 'Agregar item' },
  TABLE: { NAME: 'Nombre', EDIT_TOOLTIP: 'Editar item' },
  FORM: { NAME_LABEL: 'Nombre', NAME_PLACEHOLDER: 'Nombre del item' },
  VALIDATION: { NAME_REQUIRED: 'El nombre es obligatorio.' },
  MESSAGES: { DELETE_SUCCESS: 'Item eliminado correctamente.' },
  CONFIRM: { DELETE: '¿Desea eliminar el item "{{name}}"?' },
};
```

- El `.en.ts` exporta **la misma constante** (`export const item`) con **exactamente las mismas claves**.
- Registro en `es.ts` **y** `en.ts`, y dentro de `locale.data`: `ITEM: item,`. La clave raíz en MAYÚSCULAS es el
  prefijo que usan las plantillas.
- **Cada raíz importa su propio idioma**: `es.ts` importa `./…/item.es` y `en.ts` importa `./…/item.en`. Como ambos
  exportan la misma constante, un `en.ts` que importe un `.es` compila sin error pero muestra la pantalla en español
  con el idioma en inglés. Verifícalo siempre al registrar (lo detecta `check-i18n.js`).
- Si añades textos a una pantalla existente, edita su archivo de feature; no crees otro.

## Convención de claves

`FEATURE.SECCION.CLAVE` con secciones habituales: `TITLE`, `TITLE_ADD`, `TITLE_EDIT`, `BTN`, `TABLE`, `FORM`,
`VALIDATION`, `MESSAGES`, `CONFIRM`.

Antes de crear una clave, busca en `COMMONS` (`common.es.ts`): `BUTTONS` (SAVE, UPDATE, CANCEL, SAVING, UPDATING,
YES_DELETE…), `MESSAGES` (LOADING_DATA, SAVING_DATA, OPERATION_ERROR, FIELDS_INCOMPLETE…), `CONFIRM` (ARE_YOU_SURE…),
`TABLE` (ACTIONS, EDIT, DELETE…), `VALIDATION` (REQUIRED, MAX_LENGTH con `{{max}}`…), `TITLES`.

## Uso

```html
<h1 class="pane__title">{{ 'ITEM.TITLE' | translate }}</h1>
<input [placeholder]="'ITEM.FORM.NAME_PLACEHOLDER' | translate">
<span>{{ 'COMMONS.VALIDATION.MAX_LENGTH' | translate: { max: nameMaxLength } }}</span>
```

```typescript
private readonly translate = inject(TranslateService);
this.toastr.success(this.translate.instant('ITEM.MESSAGES.DELETE_SUCCESS'));
this.translate.instant('ITEM.CONFIRM.DELETE', { name });
```

- Importa `TranslateModule` en el `imports` del componente.
- `instant()` para toastr, SweetAlert, columnas de tabla y **etiquetas de exportación**; no uses `get().subscribe()`
  salvo que necesites reaccionar al cambio de idioma.
- Interpolación con `{{param}}` dentro del texto.

## Reglas

- Nunca texto literal en español/inglés en plantillas, toastr, Swal, columnas ni `exportColumns`.
- Toda clave nueva existe en `.es.ts` y `.en.ts` → verifícalo con
  `node "$HOME/.claude/skills/angular-webpos/scripts/check-i18n.js"` (desde la raíz del repo).
